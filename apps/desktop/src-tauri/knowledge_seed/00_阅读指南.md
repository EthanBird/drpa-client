# RPAZ 开发指南：阅读地图

欢迎使用 DRPA 内置知识库。这里的文档不是跳转到网站的帮助页，而是一套随 Host 发布、完全离线、可以编辑和扩展的 Markdown 知识库。你可以在左侧创建目录和文档，也可以导入已有的 `.md` / `.markdown` 文件；文档内的相对链接会直接打开同一知识库中的目标文件。

> 本目录描述当前 DRPA Next `schema: 2` 的真实实现。示例都以 Windows x64 离线运行时、Python 3.11、DrissionPage 和开发工作室为基线。

## 2. RPAZ 是什么

RPAZ 是扩展名为 `.rpaz` 的 ZIP 归档。归档根目录必须包含 `manifest.yaml`，代码、Notebook、锁文件和静态资源都使用包内相对路径。

```text
my-automation.rpaz
├── manifest.yaml          # schema 2 包合同，必须在根目录
├── main.py                # Python 入口
├── notebook.ipynb         # 可选，开发过程使用
├── requirements.lock      # 可选，声明给 runtime 的锁文件路径
└── assets/                # 可选，包内只读资源
```

RPAZ 同时解决四件事：

- **可识别**：`id` 与 `version` 定义一个可安装版本。
- **可运行**：`entrypoint` 定义 Host 应加载哪个模块和函数。
- **可配置**：`parameters` 让运行工作台生成输入并向 `ctx.params` 提交值。
- **可审计**：`capabilities` 明确声明网络和文件系统需求，日志与产物通过运行协议回传。

## 3. 应用中的四个开发区域

### 开发工作室

管理项目目录、编辑 `manifest.yaml` / Python / Notebook、运行代码块、直接运行工作副本和导出 RPAZ。打开已安装脚本包时，工作室会创建可编辑副本，不直接修改安装区。

### 运行工作台

选择已安装脚本包和任务配置，根据 manifest 参数创建当前值，提交一次运行。参数默认值来自 `parameters[].default`；保存的任务配置可以覆盖默认值。

### 运行记录

查看任务状态、耗时、进度、日志和产物。脚本使用 `ctx.log`、`ctx.progress()`、`ctx.output_file()` 产生这些信息。

### 知识文档

保存本地 Markdown 文档。默认指南只是起点：可以在同一知识库中加入业务页面说明、选择器笔记、故障记录、字段字典和操作手册，并使用相对链接连接这些材料。

## 4. 数据与代码的基本边界

开发时经常会遇到三种路径，它们含义不同：

| 路径 | 来源 | 用途 |
|---|---|---|
| `ctx.package_dir` | 当前项目或已安装包目录 | 读取包内源码、模板和静态资源 |
| `ctx.output_dir` | 本次运行独立输出目录 | 保存本次运行产生的文件 |
| `ctx.output_file("...")` | Host 约束后的产物路径 | 创建父目录并把文件登记为可见产物 |

不要把系统临时目录、用户桌面或固定盘符写死到脚本中。可分发任务应只读取包内资源、运行参数明确提供的路径，或 Host 允许的目录；产出优先写入 `ctx.output_file()` 返回的路径。

## 5. 最小成功标准

一个可以交付的 RPAZ 至少满足：

- [ ] `manifest.yaml` 是 schema 2，能通过工作室构建校验。
- [ ] 归档根目录直接包含 `manifest.yaml`，没有多套一层目录。
- [ ] `entrypoint.module` 存在，并定义 `callable(ctx)`。
- [ ] 所有可调输入都在 `parameters` 中声明类型、必填性和合理默认值。
- [ ] 日志说明阶段和结果，不记录口令、令牌或完整敏感页面。
- [ ] 进度值单调前进，最终成功路径报告 `100`。
- [ ] 产物通过 `ctx.output_file()` 登记，并显式使用 UTF-8 或二进制模式写入。
- [ ] 浏览器任务通过 `ctx.browser()` 获取封装浏览器，不写死 Chrome 路径。
- [ ] 在开发工作室直接运行通过，再导出并安装运行一次。

## 6. 文档中的约定

代码块中的 `ctx` 始终是 `RuntimeContext` 实例。`manifest.yaml` 使用当前实现支持的字段，不把路线图字段当成已经可用的能力。出现“默认”时区分三种含义：

1. **manifest 默认值**：`parameters[].default`，工作台首次创建参数时使用。
2. **Python 回退值**：例如 `ctx.params.get("count", 1)`，用于直接调用或旧配置缺字段。
3. **Context 内置行为**：例如 `ctx.browser(headless=None)` 会读取 `ctx.params["headless"]`，缺失时使用 `False`。

三层默认应保持一致。例如 manifest 默认 `headless: false`，Python 也使用 `False`，文档和任务配置不要再给出相反值。

## 8. 关于版本

本知识库是可编辑副本。首次初始化会写入默认目录；之后 Host 不覆盖你的修改。应用更新可以升级知识库功能，但用户创建、导入、重命名或删除的 Markdown 仍保存在数据目录 `knowledge/` 下。

如果需要保存一份外部副本，选中文档后使用“导出”。需要迁移多篇文档时，可以逐篇导出，或者在数据目录中备份整个 `knowledge/` 文件夹。
