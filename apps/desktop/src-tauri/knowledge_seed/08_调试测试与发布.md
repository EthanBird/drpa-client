# RPAZ 调试、测试与发布

本章给出从函数测试到安装后回归的分层流程。目标是尽早发现问题，并确认导出的归档在离线目标机器上仍能运行。

## 1. 测试金字塔

```text
纯函数测试                 快、稳定、无需 Host
项目模块集成测试           固定文件/响应夹具
工作室直接运行             真实 Context 和运行协议
导出 → 安装 → 工作台运行   真实归档与安装路径
离线机器回归               最终 runtime、Chrome、WebView2
```

不要只依赖最慢的 GUI 测试，也不要只跑纯函数。

## 2. 纯函数测试

把清理、解析、渲染写成无副作用函数：

```python
def safe_filename(value: str) -> str:
    ...


def test_safe_filename():
    assert safe_filename("Bing / 每日图片") == "Bing"
```

项目可建立：

```text
tests/
├── test_main.py
└── fixtures/
    └── response.json
```

测试不要实时访问网站。把去敏后的响应保存为小型 UTF-8 fixture。

## 3. Context 替身测试

对入口编排使用窄 fake：

```python
from pathlib import Path


class FakeLog:
    def __init__(self):
        self.messages = []

    def info(self, message, *args):
        self.messages.append(message % args if args else message)

    warning = info
    error = info


class FakeContext:
    def __init__(self, output_dir: Path, params=None):
        self.params = params or {}
        self.output_dir = output_dir
        self.package_dir = Path(__file__).parents[1]
        self.run_id = "test-run"
        self.package_id = "com.example.test"
        self.log = FakeLog()
        self.progress_events = []
        self.artifacts = []

    def progress(self, value, message=""):
        self.progress_events.append((value, message))

    def output_file(self, relative_path, label=""):
        target = self.output_dir / relative_path
        target.parent.mkdir(parents=True, exist_ok=True)
        self.artifacts.append((target, label))
        return target
```

然后测试：

```python
def test_main_writes_result(tmp_path):
    ctx = FakeContext(tmp_path, {"message": "hello"})
    main(ctx)
    assert (tmp_path / "result.txt").read_text(encoding="utf-8") == "hello\n"
    assert ctx.progress_events[-1][0] == 100
```

## 4. 网络夹具

把网络函数和入口分开：

```python
def fetch_json(url: str) -> dict:
    ...


def main(ctx):
    payload = fetch_json(build_url(ctx.params))
```

测试时注入或 monkeypatch：

```python
monkeypatch.setattr(module, "fetch_json", lambda url: {"items": [{"id": 1}]})
```

至少覆盖：成功、空结果、字段缺失、超时、无效 JSON。

## 5. manifest 校验

构建前检查：

- schema、ID、版本。
- 入口文件存在。
- callable 存在。
- lock 文件路径存在（如果声明）。
- 参数 ID 不重复。
- 默认值和 Python 回退一致。
- 归档路径没有 `..`、盘符或反斜杠。

工作室“导出 RPAZ”会解析 manifest 并检查入口。AI Agent 的 `rpaz_validate` 工具也可提供结构化诊断。

## 6. 工作室直接运行

至少运行三组参数：

1. 默认参数。
2. 边界参数：最小/最大条数、空可选项。
3. 一个预期失败参数：无效枚举、缺文件。

检查：

- 日志不是乱码。
- 进度不会倒退。
- 失败状态真实为 failed。
- traceback 指向项目文件。
- 产物路径在本次 output。
- 运行完成后浏览器退出。

## 7. 手工归档结构检查

RPAZ 是 ZIP，可查看列表：

```powershell
python -m zipfile -l .\build\com.example.task-0.1.0.rpaz
```

正确：

```text
manifest.yaml
main.py
assets/template.json
```

错误：

```text
my-project/manifest.yaml
my-project/main.py
```

manifest 必须在归档根目录。

## 8. 安装后回归

导出后执行：

1. 在 RPAZ 包页安装 `.rpaz`。
2. 确认包名、版本、运行时和参数摘要。
3. 在运行工作台创建任务配置。
4. 检查默认参数是否填充。
5. 运行一次。
6. 打开运行记录和产物。
7. 卸载后确认项目副本不受影响。

直接运行与安装运行的差异可以发现：归档层级错误、漏打资源、版本冲突和安装目录只读问题。

## 9. 浏览器任务回归

至少覆盖：

- 有界面模式。
- headless 模式。
- 页面正常结果。
- 页面空结果。
- 网络断开或超时。
- selector 失效时的错误信息。
- 下载完成并登记产物。
- finally 关闭浏览器。

离线环境不是“禁止访问业务网站”，而是安装和依赖准备不能依赖互联网。任务自身若声明网络能力，运行时仍可能访问业务目标。

## 10. 性能与资源

记录：

- 首次浏览器启动耗时。
- 处理 10、100、1000 条数据的耗时。
- 输出文件大小。
- 页面、tab 和文件句柄是否释放。
- 日志数量是否与数据量线性爆炸。

长列表应批量报告日志和进度。大响应流式处理或设置上限。

## 11. 发布版本策略

包版本是 `{major}.{minor}.{patch}`：

- patch：selector、小型错误处理、日志改进，不改变参数合同。
- minor：新增可选参数、输出或兼容能力。
- major：删除/重命名参数、输出结构不兼容、业务语义改变。

每次发布记录：

```markdown
## 1.2.0

- 新增 `headless` 参数，默认 true。
- JSON 结果增加 `source_url` 字段。
- 页面结构失效时生成诊断截图。
```

## 12. 离线依赖检查

- 不在代码中执行 pip。
- 不从 CDN 动态 import Python/JS。
- 浏览器使用 `ctx.browser()`。
- 包资源都在归档中。
- 新第三方库已经进入 sealed runtime wheels 和锁文件。
- 目标机断网时，除业务网络步骤外，其余初始化可完成。

## 13. 发布前总检查

### manifest

- [ ] schema 2。
- [ ] ID 和 version 合法。
- [ ] 参数有类型、required 和合理默认。
- [ ] capabilities 与实际行为一致。

### Python

- [ ] 入口为 `callable(ctx)`。
- [ ] 参数转换和范围验证完整。
- [ ] 所有网络调用有超时。
- [ ] finally 释放浏览器。
- [ ] 文本显式 UTF-8。
- [ ] 最外层异常重新抛出。

### 输出

- [ ] 最终文件使用 output_file。
- [ ] 文件非空或空结果有明确说明。
- [ ] 日志不含 secret。
- [ ] 成功后进度为 100。

### 回归

- [ ] Notebook 重启后全部运行。
- [ ] 工作室默认参数直接运行。
- [ ] 导出、安装、工作台运行。
- [ ] 目标离线 runtime 验证。
