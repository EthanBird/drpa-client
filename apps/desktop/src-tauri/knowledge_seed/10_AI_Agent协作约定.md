# AI Agent 与知识库协作约定

DRPA 的 AI Agent 面向 RPAZ 开发：阅读项目、修改文件、校验 manifest、构建包和调用 sealed Python。知识文档为 Agent 提供稳定的本地规范、业务说明和故障经验。要让 Agent 输出可复核结果，知识库和项目需要可检索、可链接、可测试。

## 1. 知识库适合保存的内容

建议每个业务自动化建立目录：

```text
业务名称/
├── 00_索引.md
├── 01_业务流程.md
├── 02_页面与字段.md
├── 03_选择器策略.md
├── 04_输入输出合同.md
├── 05_故障记录.md
└── 变更日志.md
```

索引使用相对链接：

```markdown
# 业务索引

- [业务流程](./01_业务流程.md)
- [页面与字段](./02_页面与字段.md)
- [选择器策略](./03_选择器策略.md)
```

## 2. 文档写法

### 一个术语一个稳定名称

如果 UI 叫“任务配置”，文档和 prompt 不要交替使用“运行模板”“profile”“预设”而不解释。首次出现可写：

```text
任务配置（Task Profile）是脚本包的一组本地参数当前值。
```

### 记录事实与假设

```markdown
## 已验证事实

- 登录按钮包含 `data-testid="login-submit"`。
- 成功后 URL 路径为 `/dashboard`。

## 待验证假设

- 无头模式下验证码出现频率可能更高。
```

Agent 可以优先依赖已验证事实，并为假设安排测试。

### 示例保持可运行

代码块注明文件和上下文：

```python
# main.py
def main(ctx):
    ...
```

YAML 使用当前 schema 2，不混入尚未实现的字段。

## 3. 不写入知识库的内容

- API key、口令、cookie、token。
- 未脱敏的客户数据。
- 浏览器 profile 或完整网络抓包。
- 可从源码准确推导、但容易过时的复制代码全文。
- 大体积二进制。

凭据放在凭据保险箱或运行配置引用中。知识库只写凭据名称和使用步骤。

## 4. Agent 当前工具边界

AI Agent 配置 OpenAI-compatible URL、model 和可选 key。绑定开发项目后，可使用面向 RPAZ 的窄工具：

| 工具 | 用途 |
|---|---|
| `knowledge_list_documents` | 列出本地知识目录和文档 |
| `knowledge_read_document` | 读取 UTF-8 Markdown 文档 |
| `knowledge_write_document` | 创建或更新 Markdown 文档及安全父目录 |
| 项目文件列表 | 查看项目结构 |
| 文件读取 | 读取项目内文本 |
| 文件写入 | 创建或更新项目文件 |
| `rpaz_validate` | 校验 manifest 与入口 |
| `rpaz_build` | 构建 `.rpaz` |
| `rpaz_python` | 在 sealed Python 中运行有限代码辅助分析 |

工具限制在项目根目录和规定执行时间内。Agent 不应通过 prompt 假设自己已经执行了未返回工具结果的操作。

知识库 Host API 与项目 API 分离，但 Agent 已通过三个 knowledge 工具复用同一套安全相对路径、UTF-8、大小限制和原子写入规则。即使会话没有绑定开发项目，知识工具仍可使用；六个 RPAZ 项目工具需要先绑定项目。

## 5. 高质量任务提示

```text
读取当前项目 manifest.yaml 和 main.py。
目标：新增 headless 布尔参数，默认 true，并让 ctx.browser 使用它。
要求：保持其他参数兼容；更新项目 README；运行 rpaz_validate；列出修改文件和验证结果。
```

包含：

- 当前对象。
- 预期行为。
- 兼容约束。
- 应更新的文档。
- 应执行的验证。

## 6. 让 Agent 修复失败

提供最小证据：

```text
运行 ID：...
失败阶段：打开搜索页后定位结果
最后日志：页面已加载，但结果容器为空
错误：没有找到结果项
预期：至少收集标题和 URL
```

不要只写“运行不了”。可以把去敏后的 traceback、相关页面片段或响应 fixture 保存成项目测试文件。

## 7. Agent 修改后的门禁

- [ ] 展示文件 diff 或修改摘要。
- [ ] `rpaz_validate` 通过。
- [ ] 纯函数测试通过。
- [ ] 工作室直接运行通过。
- [ ] 输出合同未意外变化。
- [ ] manifest 默认与 Python 默认一致。
- [ ] 文档同步更新。

Agent 生成代码不等于任务完成；工具返回和运行结果才是证据。

## 8. 会话管理

一个会话绑定一个主要项目和一个清晰目标。建议标题：

```text
Bing 图片包：流式下载与错误处理
Bilibili 搜索：修复结果选择器
发票导出：新增 2026-07 字段映射
```

目标改变时新建会话，避免长对话把旧约束带入新任务。会话中不要粘贴 key；Agent 配置面板中的 key 是会话级可选配置。

## 9. 文档变更记录

```markdown
## 2026-07-14

- 页面结果卡由 `.old-card` 改为 `[data-testid=result-card]`。
- 已在 headless=true 下验证 20 条结果。
- 旧 selector 保留为第二回退，计划下个 major 删除。
```

记录日期、变化、验证条件和兼容决定。Agent 后续可以理解为什么存在多个 selector。

## 10. 知识文档的本地链接

同目录：

```markdown
[选择器策略](./03_选择器策略.md)
```

上级目录：

```markdown
[团队字段字典](../共享/字段字典.md)
```

知识文档会拦截相对 `.md` 链接并在当前库中打开。外部 `https://` 链接仍是外部资源，离线环境下可能不可访问，因此关键步骤应写入本地文档，而不是只保存网址。

## 11. 导入与导出

- 从 Notion、思源或仓库导出的 Markdown 可以通过“导入”加入当前目录。
- 同名文件导入时 Host 自动追加 `(1)`、`(2)` 等后缀。
- 文档必须是 UTF-8，单篇有大小限制。
- 导出当前文档得到普通 Markdown，不绑定 DRPA 专有格式。
- 目录层级迁移可在数据目录备份整个 `knowledge/`。

## 12. 面向未来的索引

后续知识检索可以按以下元数据建立索引：

- 文件相对路径。
- 标题和标题层级。
- Markdown 链接图。
- 最近修改时间。
- 与项目 ID、package ID 的显式关联。

现在就保持清晰文件名、稳定标题和索引页，可以降低未来向量检索或全文检索的噪音。

## 13. 协作完成定义

一次 Agent 辅助开发完成时，应能回答：

1. 修改了哪些项目文件？
2. 为什么这样修改？
3. 哪些规范或业务文档支持这个决定？
4. 执行了哪些校验与测试？
5. 产物在哪里？
6. 仍有哪些假设或已知限制？

把答案写入会话摘要或项目变更日志，知识库就会从静态说明成长为可持续维护的本地工程记忆。
