# 日志、运行事件与错误处理

DRPA 的运行工作台不是终端复刻。它需要把任务阶段、进度、业务日志、异常和产物变成结构化事件，供 UI 展示、运行记录保存和后续 AI Agent 分析。

## 1. 一次运行的事件顺序

典型成功运行：

```text
Host 创建 run
Worker emit ready
package emit log / progress / artifact
Worker emit completed(exit_code=0)
Host 更新运行状态为 success
```

典型失败运行：

```text
Host 创建 run
Worker emit ready
package emit log / progress
入口抛出异常
Worker emit error(message, traceback)
Worker emit completed(exit_code=1)
Host 更新运行状态为 failed
```

所有 Runtime 事件使用 JSON Lines。`EventWriter` 为每个事件添加递增 `sequence`，使用 ASCII 安全 JSON 写入 stdout，并立即 flush。这避免包日志中的中文导致 Host 按无效 UTF-8 读取协议流。

## 2. 日志级别

| 级别 | 使用场景 | 示例 |
|---|---|---|
| `info` | 正常阶段、数量、结果摘要 | `采集完成 · count=24` |
| `warning` | 可恢复偏差、降级、数据为空 | `主选择器失效，使用备用策略` |
| `error` | 即将失败或局部失败 | `文件写入失败 · name=result.csv` |
| `exception` | 在 except 中记录 traceback | `浏览器流程失败` |

默认 logger 级别是 INFO，所以 debug 通常不显示。需要诊断时优先增加有意义的 INFO，而不是输出每个循环对象。

## 3. 专业日志格式

推荐结构：

```text
动作/结果 · key=value · key=value
```

示例：

```python
ctx.log.info("任务开始 · market=%s · count=%s", market, count)
ctx.log.info("接口响应完成 · status=%s · images=%s", status, len(images))
ctx.log.warning("字段缺失 · field=%s · item=%s", "title", item_id)
ctx.log.info("产物就绪 · name=%s · bytes=%s", target.name, target.stat().st_size)
```

不推荐：

```python
ctx.log.info("开始")
ctx.log.info("处理中...")
ctx.log.info(str(huge_payload))
ctx.log.info(f"token={token}")
```

每条日志应帮助回答：正在做什么、处理了多少、用了哪种策略、结果在哪里、为什么失败。

## 4. 阶段设计

把任务拆成 4 到 8 个用户可理解阶段：

```python
ctx.log.info("阶段 1/4 · 参数校验")
validate_params(...)
ctx.progress(5, "参数已确认")

ctx.log.info("阶段 2/4 · 获取数据")
records = fetch(...)
ctx.progress(55, f"已获取 {len(records)} 条")

ctx.log.info("阶段 3/4 · 标准化数据")
normalized = normalize(records)
ctx.progress(80, "数据已标准化")

ctx.log.info("阶段 4/4 · 写入产物")
write_outputs(normalized)
ctx.progress(100, "任务完成")
```

阶段名稳定后，运行日志更容易比较，也方便 Agent 定位失败点。

## 5. 异常处理策略

### 让不可恢复错误向上抛出

```python
if not records:
    raise RuntimeError("接口返回成功，但没有 records 字段")
```

Runtime 会捕获入口异常，发送 error 与完整 traceback，并以 exit code 1 结束。不要在最外层吞掉异常后正常返回，否则 Host 会把失败误标为成功。

错误示例：

```python
def main(ctx):
    try:
        run(ctx)
    except Exception as exc:
        ctx.log.error("失败：%s", exc)
        return  # Host 将认为成功
```

正确示例：

```python
def main(ctx):
    try:
        run(ctx)
    except Exception:
        ctx.log.exception("任务失败")
        raise
```

### 局部可恢复错误

```python
results = []
for index, item in enumerate(items, start=1):
    try:
        results.append(process(item))
    except KnownOptionalError as exc:
        ctx.log.warning("条目跳过 · index=%s · reason=%s", index, exc)
```

只有明确可恢复的异常才逐项忽略。不要 `except Exception: continue`，这会把 selector 失效、编码错误和磁盘故障都变成“结果为空”。

## 6. 错误消息设计

好的错误消息包含：

- 失败对象：哪个文件、页面、字段或阶段。
- 已知事实：状态码、条目索引、允许范围。
- 下一步：检查参数、登录状态或页面结构。

```python
raise ValueError(f"image_count={count} 超出范围，允许 1..8")
raise RuntimeError(f"搜索页面没有结果容器：url={page.url}")
raise RuntimeError(f"写入 CSV 失败：target={target.name}") from exc
```

错误消息中避免口令、token、cookie、完整请求头和个人数据。

## 7. traceback 与异常链

保留原始原因：

```python
try:
    payload = json.loads(raw_text)
except json.JSONDecodeError as exc:
    raise RuntimeError("接口返回的内容不是有效 JSON") from exc
```

Runtime 的 traceback 会显示异常链，Agent 和开发者可以看到根因位置。

如果异常文本本身包含敏感 URL 参数，先构造脱敏业务异常，而不是直接 `raise RuntimeError(str(exc))`。

## 8. 网络错误

```python
from urllib.error import HTTPError, URLError

try:
    with urlopen(request, timeout=30) as response:
        payload = response.read()
except HTTPError as exc:
    raise RuntimeError(f"接口返回 HTTP {exc.code}") from exc
except URLError as exc:
    raise RuntimeError(f"接口连接失败：{exc.reason}") from exc
```

必须设置超时。重试只应用于短暂错误，并限制次数：

```python
for attempt in range(1, 4):
    try:
        return fetch_once()
    except TemporaryNetworkError:
        if attempt == 3:
            raise
        ctx.log.warning("请求暂时失败 · attempt=%s/3", attempt)
        time.sleep(attempt)
```

登录失败、参数错误、404 等确定性错误不应盲目重试。

## 9. 浏览器诊断

```python
try:
    execute_flow(page)
except Exception:
    ctx.log.error("页面流程失败 · url=%s · title=%s", page.url, page.title)
    screenshot = ctx.output_file("diagnostics/page-failure.png", "失败截图")
    try:
        page.get_screenshot(path=str(screenshot), full_page=True)
    except Exception as screenshot_error:
        ctx.log.warning("失败截图未生成 · reason=%s", screenshot_error)
    raise
```

诊断动作自身失败时不要覆盖主异常。

## 10. 资源清理

文件和临时目录应按异常安全方式清理。浏览器仍可使用常见的 `finally` 写法，但 RPAZ Runtime 会把 `page.quit()` 解释为释放当前脚本句柄，成功和失败都保留共享 Chrome 供溯源与后续任务复用：

```python
page = ctx.browser()
try:
    run_browser(page)
finally:
    page.quit()
```

标准文件对象使用 with：

```python
with target.open("wb") as output:
    output.write(data)
```

临时文件可以在 finally 删除，但最终产物不要在清理阶段误删。

## 11. 进度与失败

失败前不要把进度提前设为 100：

```python
ctx.progress(90, "数据已获取，正在写入")
write_output()
ctx.progress(100, "任务完成")
```

异常时通常不需要再调用 progress；error/completed 事件会确定最终状态。若需要阶段提示，先写 error 日志再抛出。

## 12. 取消

Runtime 对 `KeyboardInterrupt` 有专门处理：发送 warning `run cancelled`，再发送 `completed(exit_code=130)`。任务中的长循环应避免永久阻塞，并为网络、等待、子进程设置超时，让取消可以被处理。

## 13. 日志量控制

不要每条数据都输出日志。可以按批次：

```python
for index, item in enumerate(items, start=1):
    process(item)
    if index == 1 or index % 100 == 0 or index == len(items):
        ctx.log.info("批处理进度 · completed=%s · total=%s", index, len(items))
```

详细数据写入产物，日志只保留索引和统计。

## 14. 完整异常安全入口

```python
def main(ctx):
    ctx.log.info("任务开始 · package=%s · run=%s", ctx.package_id, ctx.run_id)
    page = None
    try:
        config = parse_config(ctx.params)
        ctx.progress(5, "参数已确认")
        page = ctx.browser(headless=config.headless)
        records = collect(page, config, ctx)
        ctx.progress(80, f"已收集 {len(records)} 条")
        target = write_report(ctx, records)
        ctx.log.info("产物就绪 · name=%s · bytes=%s", target.name, target.stat().st_size)
        ctx.progress(100, "任务完成")
    except Exception:
        ctx.log.exception("任务失败")
        raise
    finally:
        if page is not None:
            page.quit()
```
