# 流程设计

## 入口与用途

从左侧主导航进入“流程设计”。这是兼容 Dify DSL 与 Dify 风格 Service API 的本地流程开发、调试和发布工作台。

## 从创建到发布

1. 先打开 “Providers”，创建 OpenAI Chat Completions 兼容连接并测试。
2. 点击“新建流程”，选择 Chat、Completion、Workflow 或 Chatflow。
3. Chat/Completion 主要配置 Prompt 和输入变量；Workflow/Chatflow 还可在可视化画布编排节点与连线。
4. 在“调试预览”输入测试消息，检查流式输出、模型、耗时和 Token。
5. 在“运行记录”复核完整输入输出。
6. 发布前运行兼容性检查；通过后可发布本地版本或导出 Dify DSL。
7. 在“API 与导出”启动本机 Service，发布后的流程通过 Bearer Token 调用。

## 工作流使用建议

- 先建立 Start → LLM/代码/RPAZ → Answer/End 的最短可运行链，再逐步增加条件、迭代、知识检索等节点。
- 每次增加节点后都先保存并调试，避免同时排查 Provider、变量映射和连线问题。
- RPAZ 节点引用当前工作区已安装包；知识检索节点引用当前工作区的向量知识库。

## 安全与限制

- 本地 Service 默认只应监听 `127.0.0.1`；不要在不了解网络边界时对外暴露。
- API Token 和 Provider 密钥属于敏感信息，不要写入导出的 DSL、截图或知识文档。
- 删除流程会删除配置和本地 API Token，但历史运行记录仍会保留。
- 导出兼容性检查会提示本机专属节点或 Provider 映射问题；存在阻止项时不能导出。
