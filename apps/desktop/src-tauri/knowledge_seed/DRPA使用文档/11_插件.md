# 插件

## 页面用途

“插件”是清单驱动的扩展工作台。插件通过 manifest 声明后台服务、配置、工具、Provider、API 调试端点、事件和受限面板；DRPA 统一生成管理与调试界面，而不是为每个插件硬编码页面。

## 适用场景

- 安装并管理第三方或内置插件。
- 启停本地后台服务并检查健康。
- 配置 AI Provider 或让插件工具接入 Agent。
- 调试 manifest 声明的 HTTP Endpoint。
- 查看结构化流量事件与服务日志。
- 创建新的插件项目和能力模板。

## 前置条件

- 插件目录必须有合法 manifest 和与其声明一致的入口/资源。
- 服务插件所需端口不能被占用。
- Provider/工具要接入 Agent，还需在[设置](14_设置.md)启用“Skills 与插件工具”。
- 第三方插件应先完成来源与权限审查。

## 界面区域

1. **顶部操作**：刷新、安装、创建插件项目。
2. **左侧插件目录**：状态、选择与侧栏收起。
3. **插件标题与状态**：启用/停用、卸载等。
4. **能力页签**：由 manifest 动态生成，常见为概览、配置、服务、工具、API 调试、流量和日志。
5. **配置表单**：由 `config.schema.json` 生成。
6. **自定义面板**：在受限 iframe 中运行。

## 安装和启用流程

1. 安装或选择插件。
2. 在清单信息检查 ID、版本、目录、来源和声明能力。
3. 打开配置：
   - 普通字段按说明填写；
   - secret 字段留空通常表示保持已有值。
4. 保存后启用插件。
5. 服务类插件启动后台服务并立即运行健康检查。
6. 观察端口、进程、自定义探针和日志。
7. 需要 Agent 使用时，确认 manifest 已声明 Provider/工具，再到 AI Agent 检查工具列表。

## API 调试流程

1. 打开“API 调试器”。
2. 从左侧选择 manifest 声明的端点。
3. 检查 HTTP 方法、相对 Endpoint、请求参数和超时。
4. 发送请求。
5. 查看状态码、Content-Type、耗时和响应正文。
6. 再到“流量事件”按 req_id 或类型筛选，结合服务日志定位。

宿主代理只允许清单声明端点，不是任意网络请求器。

## 状态与字段解释

- **enabled/disabled**：是否允许插件能力工作。
- **running/stopped/error**：后台服务进程状态。
- **autostart**：应用启动时是否自动启动服务。
- **health**：进程、端口和自定义探针综合结果。
- **Provider**：只有 manifest `providers[]` 声明的连接才能接入 Agent。
- **Tool**：参数 schema 和调用入口来自 manifest。
- **Endpoint timeout**：宿主代理单次请求上限。
- **结构化 event**：宿主解析的事件；旧插件可能通过兼容 stdout 格式上报。

## 限制与安全

- manifest 是权限契约，但启用第三方可执行文件前仍需人工审查。
- 自定义面板使用受限 iframe，不应获得任意桌面或文件能力。
- 密钥写入 secret 配置，不要放在 manifest、调试正文或日志。
- 工具和调试请求受声明端点、权限、超时与宿主代理限制。
- 卸载可能移除插件文件和配置；重要插件项目或诊断信息先备份。
- 自动启动会增加开机资源和端口占用，只对必要服务启用。

## 常见问题与排错

- **服务启动后立刻停止**：查看服务日志，检查入口、依赖、端口和配置。
- **健康检查失败但进程在**：端口或自定义探针失败；查看具体检查项。
- **Agent 看不到 Provider/工具**：manifest 必须声明、插件已启用、设置扩展权限开启。
- **API 调试被拒绝**：请求端点未在 manifest 声明，或方法/权限不匹配。
- **修改配置未生效**：保存后按插件设计重启服务，再做健康检查。
- **自定义面板功能受限**：这是 iframe 沙箱边界；需要宿主能力应通过清单工具/端点声明。
- **卸载按钮有风险提示**：先确认目录和需保留数据，卸载不是停用的同义操作。
