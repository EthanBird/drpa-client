# 扩展工具

## 页面用途

“扩展工具”集中管理 AI Agent 的内置工具权限、Skills/插件工具和当前工作区安装的离线 QuickJS 扩展。它控制模型能看到哪些工具，Host 在真正执行时还会再次校验权限和路径。

## 内置工具

1. 使用总开关决定 Agent 是“仅模型对话”还是允许工具调用。
2. 按任务启用分类权限；关闭的分类不会发送对应工具定义。
3. 文件能力分为：
   - `find_files`：按 glob 快速查找项目文件，遵循 `.gitignore`；
   - `search_text`：在项目内做正则或字面量检索；
   - `read_file`：从指定起始行读取文本，单次最多 2000 行；
   - `edit_file`：只在绑定项目内进行一次唯一匹配的精确替换。
4. 数据库查询工具始终只读；创建连接只保存连接元数据，不保存密码。
5. Python 和项目编辑必须绑定通用项目；具有 RPAZ 规范的项目额外获得校验和构建工具。

## 安装离线扩展

1. 切到“扩展”页签，点击“安装本地扩展”。
2. 选择 `.js`、`.mjs` 或 npm `.tgz` 离线包。
3. Host 在临时目录解包并预检入口、工具定义、路径和规模；成功后才提交到当前工作区。
4. 查看扩展卡片中的来源、版本、校验摘要、目录和实际注册工具。
5. 可单独停用扩展；非内置扩展可卸载。

扩展采用 Pi 风格接口：

```js
export default function (pi) {
  pi.registerTool({
    name: "project_summary",
    label: "项目摘要",
    description: "统计当前项目文件",
    parameters: { type: "object", properties: {} },
    execute() {
      const result = pi.hostcall("find_files", { pattern: "**/*", limit: 200 });
      return { content: [{ type: "text", text: `共 ${result.files.length} 个文件` }] };
    }
  });
}
```

`pi.hostcall` 只能调用当前策略允许的 DRPA Host 工具，不能递归调用另一个 QuickJS 扩展。

## 离线兼容边界

- 当前运行时面向无外部依赖的单文件 JavaScript bundle。
- TypeScript 入口、Node 内置模块和未打包的外部 `import` 会在安装预检时拒绝，并显示原因。
- QuickJS 设有内存、栈和执行时间上限；扩展不能获得任意本机能力，只能通过受控 hostcall。
- 原生 Pi 扩展若依赖终端 UI、子进程、Git worktree 或 Node 包解析，需要先在可信环境打包/改造，不能用空 shim 假装兼容。
- `@narumitw/pi-subagents` 的入口是 TypeScript 且依赖 Node/Pi 运行环境，因此当前会明确拒绝；内置无依赖示例用于验证安装和 hostcall 链路。

## 安全与排错

- 扩展属于当前工作区，不会自动跨工作区启用。
- 安装来源不明的 JS 仍有风险；先审查代码和校验摘要。
- 扩展开关不可用时，先启用总工具开关以及“Skills、插件与 QuickJS”分类。
- 安装提示“单文件 bundle”时，应在联网开发机完成依赖打包，再把产物离线导入。
- 工具可见但 hostcall 被拒绝时，启用它所调用的内置工具分类，并确认会话已绑定项目。
