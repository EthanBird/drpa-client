# 运行环境

## 页面用途

“运行环境”展示 DRPA 封装的 Python + RPA 环境、Jupyter Kernel、浏览器自动化依赖，以及本机 CPU、物理内存和本地磁盘使用情况，并提供高成本的离线重建入口。

## 适用场景

- 开发或运行前确认内置 Python 可用。
- Notebook 无法启动时检查 Kernel。
- DrissionPage 无法打开浏览器时检查依赖。
- 任务缓慢或卡顿时观察 CPU、内存、磁盘。
- 确认运行时文件确实损坏后执行重建。

## 前置条件

无需管理员权限。资源监控使用普通用户可读取的系统接口，每 2 秒刷新；Windows 与 Linux 的数据来源不同，但不会安装驱动或提权。

## 界面区域

1. **环境摘要**：版本、平台、环境状态和根路径。
2. **Python + RPA 卡片**：封装 Python 与自动化依赖。
3. **Jupyter Kernel 卡片**：开发工作室交互 Kernel。
4. **浏览器自动化卡片**：Chrome/DrissionPage 等。
5. **本机资源监控**：CPU、内存、磁盘总量与每个本地卷。
6. **强制重建**：二次确认后离线重建整个 `runtime-environment`。

## 日常检查流程

1. 打开页面，等待首个资源采样。
2. 确认三个运行能力卡片没有异常。
3. 记录 Python/环境路径，确认它是 DRPA 数据目录而不是系统 Python。
4. 查看 CPU：首次需要两个计数器时间点，短暂“正在采样”正常。
5. 查看内存已用/总量。
6. 查看磁盘，特别关注工作区和运行环境所在卷的剩余空间。
7. 回到[开发工作室](03_开发工作室.md)运行最小 Python 单元验证。

## 指标与状态解释

- **CPU 使用率**：两个采样间系统繁忙时间比例；瞬时尖峰不代表持续瓶颈。
- **逻辑核心**：系统报告的线程核心数。
- **内存使用率**：物理内存已用/总量，不是单个 DRPA 进程占用。
- **磁盘使用率**：本地卷聚合，并列出挂载点。
- **读取异常**：系统接口采样失败；若已有旧数据，页面可能保留最后快照。
- **环境 ready/异常**：封装运行时自检结果。

## 强制重建流程

仅在路径缺失、依赖损坏或明确自检失败时使用：

1. 保存开发工作室文件和 Notebook。
2. 停止/等待所有运行任务。
3. 记录错误与环境路径。
4. 点击“强制重建运行环境”。
5. 阅读确认：Studio Kernel 会停止，`runtime-environment` 会删除并离线重建；项目、RPAZ 包和产物保留。
6. 确认并等待数分钟，不要强制关闭应用。
7. 重建后回到本页检查，再运行最小单元。

## 限制与安全

- 资源监控是整机级采样，不是每个任务的性能分析器。
- 不需管理员权限，也不会显示需提权才能读取的硬件遥测。
- 强制重建不会修复源码、参数、Provider、数据库或网络。
- 重建期间不要运行任务或关闭电源。
- 磁盘接近满时先清理可确认的产物或迁移工作区，避免手工删除运行环境内部文件。

## 常见问题与排错

- **CPU 一开始显示横线**：等待第二次采样，约 2 秒。
- **磁盘卷数量与资源管理器不同**：只统计可读取的本地卷，网络盘或特殊挂载可能不列入。
- **资源高但任务不快**：确认是其他进程还是 DRPA；本页不做进程级归因。
- **Kernel 不可用但 Python 正常**：先关闭开发工作室再打开；仍失败再考虑重建。
- **浏览器自动化失败**：区分浏览器缺失、页面元素超时和网站限制；只有第一类适合重建。
- **重建后仍失败**：问题可能在项目代码或外部服务，回到运行记录读取 traceback。
- **无管理员权限能否使用监控**：可以，这是该监控的设计前提。
