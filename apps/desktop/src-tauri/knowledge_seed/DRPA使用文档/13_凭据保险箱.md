# 凭据保险箱

## 页面用途

“凭据保险箱”是敏感值管理的预留入口。当前版本尚未接入完整 Host 凭据服务，因此页面明确显示开发中，不提供伪造的保存、读取或绑定操作。

## 适用场景

当前适合用于了解凭据设计边界，而不是存储生产秘密。需要输入 Provider Key 或数据库密码时，应使用对应页面当前提供的临时/安全配置方式。

## 前置条件

无。看到入口不代表凭据已被加密持久化，也不代表其他页面的秘密会自动迁入保险箱。

## 界面区域（当前状态）

- 页面标题与设计说明。
- “开发中”禁用按钮。
- 提示：尚未完成的操作不会伪装可用。

当前没有凭据列表、新建表单、复制、轮换、授权或删除能力。

## 当前可用的敏感值处理方式

- **AI Agent API Key**：直接输入时只保留当前应用会话，不写入磁盘；插件 Provider 可通过宿主引用。
- **流程 Provider API Key**：在 Providers 对话框管理，不应写入流程 DSL。
- **远程数据库密码**：只保留到本次应用退出，重启后重新输入。
- **插件 secret 配置**：使用 schema 声明的 secret 字段，不写入 manifest 或日志。

## 目标设计中的字段与状态

未来凭据条目应至少区分：

- 稳定引用 ID，而不是把真实值传给项目；
- 使用范围（工作区、插件、Provider、RPAZ）；
- 创建/更新时间和轮换状态；
- 是否可用、已撤销或需要重新授权；
- 使用审计，不记录真实值。

这些是设计目标，不表示当前页面已经实现。

## 与其他页面协作

- [设置](14_设置.md)管理 Agent 临时 Key 和工具权限。
- [数据工作台](04_数据工作台.md)临时持有数据库密码。
- [流程设计](08_流程设计.md)管理 Provider。
- [插件](11_插件.md)管理 secret 配置。
- [运行工作台](05_运行工作台.md)中的 secret 参数不应进入普通日志。

## 限制与安全

真实凭据不得进入：

- RPAZ 包、manifest 或项目源码；
- Notebook 输出和运行日志；
- AI Agent 对话、AGENTS.md、MEMORY.md；
- 知识文档或向量知识库；
- 流程 DSL、插件 manifest 和 API 调试正文；
- 工作区导出包中的普通配置文件。

在完整保险箱实现前，不要自行在工作区创建 `passwords.md`、JSON 或 Python 常量保存秘密。

## 常见问题与排错

- **为什么按钮不能点**：功能尚未接入，这是有意禁用。
- **Agent Key 重启后消失**：直接输入的 Key 仅会话保存，属于安全设计。
- **数据库总要重输密码**：远程密码不持久化；当前版本需每次应用会话输入。
- **能否把密码放 MEMORY.md**：不能，MEMORY.md 会进入 Agent 上下文。
- **插件显示“已配置，留空保持”**：表示宿主持有已有 secret；不要为了查看而覆盖它。
- **导出工作区是否包含密钥**：设计上临时 Key/密码不应进入导出，但导出仍包含业务数据，必须安全保管。
