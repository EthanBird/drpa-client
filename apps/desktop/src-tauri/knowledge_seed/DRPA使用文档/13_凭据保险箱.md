# 凭据保险箱

## 页面用途

“凭据保险箱”在本机加密保存开发账号、API Key、访问令牌、数据库密码、SSH 信息和安全备注。它提供统一的创建、搜索、读取、更新、删除、收藏和分类能力，也可以在用户验证后供 AI Agent 与本机开发服务调用。

保险箱不依赖云端账号。初始化使用 Google Authenticator 兼容二维码和 6 位动态验证码；通过验证后，解密密钥只在当前 DRPA 进程内保留，退出软件、手动锁定或 24 小时到期后失效。

## 适用场景

- 保存 OpenAI-compatible Provider 的 URL、账号和 API Key。
- 保存开发/测试数据库的用户名、密码和连接说明。
- 为 RPAZ Agent 或 JCode Agent 按需提供某一条凭据。
- 让同一台电脑上的开发服务通过 loopback API 读写凭据。
- 保存不应进入项目、知识文档、日志或流程 DSL 的安全备注。

## 首次初始化

1. 打开“基础设施 → 凭据保险箱”。
2. 点击“生成初始化二维码”。二维码只在本次 10 分钟初始化会话中有效。
3. 在手机 Google Authenticator 中添加账号并扫描二维码；无法扫码时使用页面中的 Base32 手动密钥。
4. 输入手机显示的 6 位验证码，点击“验证并创建保险箱”。
5. 页面只在此时显示恢复码。立即复制或下载恢复码文件，并保存到与 DRPA 数据目录分离的离线位置。
6. 点击“我已妥善保存”进入保险箱。

6 位 TOTP 是用户在场验证，不是直接拿六位数字加密文件。Host 会生成随机 256-bit Vault Key，使用 AES-256-GCM 加密完整 Payload；Windows 使用当前用户 DPAPI 保护设备材料。

## 日常解锁与恢复

### 动态验证码

1. 打开锁定页面。
2. 选择“动态验证码”，输入 Google Authenticator 当前 6 位数字。
3. 验证成功后页面显示“已解锁”和到期时间。

允许前后各一个 30 秒时间窗口，以容忍轻微时钟偏差。连续失败会触发渐进式等待。手机和电脑时间偏差过大时，应先校准系统时间。

### 恢复码

1. 切换到“恢复码”。
2. 输入初始化时保存的分组恢复码。
3. 恢复成功后旧恢复码立即作废，页面会展示新的恢复码。
4. 下载并替换原离线备份，再确认关闭提示。

恢复码可以独立解封 Vault Key。丢失 Google Authenticator 和恢复码后，现有密文数据没有重置入口。

## 三栏工作区

### 左侧分类

- **全部项目**：所有凭据。
- **收藏**：标记星标的常用凭据。
- **类型**：登录账号、API Key、访问令牌、数据库、SSH、安全笔记。
- **本地凭据服务**：设置端口并启动/停止 loopback API。

### 中间列表

搜索会匹配名称、账号、地址和标签。列表只读取摘要，不包含 secret 与安全备注。点击条目后才由 Host 在解锁状态下读取详情。

### 右侧详情

- 名称和类型；
- 账号/标识；
- 密码/Secret（默认遮挡，可临时显示或复制）；
- 网站/服务地址；
- 逗号分隔标签；
- 加密安全备注；
- 收藏、保存和删除确认。

新增或编辑时，全部字段作为一个加密 Payload 重新写入。保存采用临时文件、备份和替换流程，异常中断不会先删除上一份有效文件。

## 本地服务

服务默认停止，只能从已解锁的保险箱页面手工启动，只监听 `127.0.0.1`，默认端口 `34131`。

第一步提交一次动态验证码：

```http
POST http://127.0.0.1:34131/v1/vault/session/verify
Content-Type: application/json

{"code":"123456"}
```

响应中的 `token` 是本次 DRPA 运行时随机 Bearer Token：

```http
Authorization: Bearer RUNTIME_TOKEN
```

可用路由：

- `GET /v1/vault/health`
- `GET /v1/vault/credentials`
- `POST /v1/vault/credentials`
- `GET /v1/vault/credentials/{id}`
- `PUT /v1/vault/credentials/{id}`
- `DELETE /v1/vault/credentials/{id}`

手动锁定、24 小时到期或退出 DRPA 后 Token 失效。服务没有开放局域网监听，也没有宽松 CORS；不要把 Token 写入项目、命令历史或日志。

## AI Agent 调用

RPAZ Agent 与 JCode Agent 都内置：

- `vault_list_credentials`：只列摘要；
- `vault_get_credential`：按 ID 读取一条完整凭据；
- `vault_upsert_credential`：创建或更新一条凭据。

使用前必须由用户在保险箱页面完成验证解锁。读取 secret 的原始工具结果只提供给当前模型回合，DRPA 持久会话和工具时间线保存脱敏事件。模型 Provider 仍会收到本次明确读取的值，因此应使用可信 Provider，并让 Agent 只取任务所需的单条凭据。

## 数据位置与安全边界

- 密文：安装数据根目录 `credential-vault/vault.json`；保险箱为应用级，不随单个工作区切换。
- Windows 设备保护：当前 Windows 用户 DPAPI。
- Payload：AES-256-GCM，名称、URL、标签和 secret 都在密文中。
- 内存会话：Vault Key 与服务 Token 使用可清零容器，最长 24 小时。
- 恢复：160-bit 随机恢复码，成功使用立即轮换。

保险箱主要防止磁盘文件、备份或工作区材料直接暴露明文。已控制当前 Windows 登录会话、具有管理员/内核权限、能够注入 DRPA 进程或记录键盘的程序属于更高信任层。安装包来源和系统本身仍需可信。

真实凭据不应进入：

- RPAZ 包、manifest、源码或 Notebook；
- 运行参数、日志、错误回溯和产物清单；
- AI 普通消息、AGENTS.md、MEMORY.md；
- 知识文档、向量知识库和流程 DSL；
- 插件 manifest 与 API 调试正文。

## 常见问题与排错

- **验证码总是错误**：校准手机和电脑时间，确认扫描的是当前 DRPA 初始化二维码。
- **提示等待重试**：连续验证失败触发退避，按页面秒数等待。
- **关闭软件后又锁定**：运行时密钥不会跨进程持久化，这是预期行为。
- **恢复后出现新恢复码**：旧码已作废，立即更新离线文件。
- **Agent 提示保险箱已锁定**：回到本页完成 6 位验证码验证，再重试工具调用。
- **外部服务连接被拒绝**：先解锁并启动本地服务，确认端口未被其他程序占用。
- **Bearer Token 失效**：手动锁定、到期或重启后重新调用 `/session/verify`。
- **密文损坏**：保留 `credential-vault` 原目录副本，不要覆盖；使用恢复码无法修复被篡改或截断的 Payload。
