# 运行记录

## 页面用途

“运行记录”是当前工作区的执行审计中心。它保存每次 RPAZ 运行的摘要、持久化事件、参数和登记产物，适合排错、复核和追溯。

## 适用场景

- 确认一次手工或定时运行的最终状态。
- 按 run ID、包或任务配置定位问题。
- 筛选 ERROR/WARN 日志并复制给开发人员。
- 打开输出目录或复制产物路径。
- 比较实际运行参数与预期配置。

## 前置条件

至少有一次由运行工作台、自动化计划或流程触发的 RPAZ 执行。没有记录时页面显示空状态。

## 界面区域

1. **运行列表**：状态、运行 ID、包、配置、开始时间、耗时和进度。
2. **搜索框**：按运行 ID、RPAZ 包或任务配置过滤。
3. **详情标题**：显示所选运行与“输出目录”按钮。
4. **概览**：终态与时间摘要。
5. **日志**：搜索、级别筛选、复制和事件列表。
6. **产物**：名称、路径、大小和复制路径。
7. **参数**：本次提交的实际参数快照。

## 审计流程

1. 搜索包名、配置或 run ID。
2. 选择一条记录，先看状态和时间。
3. 失败时切到“日志”，筛选 ERROR，再向前阅读 WARN 和相关 scope。
4. 成功时切到“产物”，确认数量、大小和路径。
5. 若业务结果异常，切到“参数”核对本次实际值。
6. 点击“输出目录”直接打开本次产物目录。
7. 需要共享日志时先搜索和筛选，再点击“复制日志”，减少无关内容。

## 状态解释

- **queued/排队中**：等待宿主资源。
- **running/运行中**：入口进程仍在执行。
- **success/成功**：入口正常结束；仍要验证业务产物。
- **failed/失败**：脚本、参数、外部系统或宿主返回错误。
- **cancelled/已取消**：收到明确取消请求。
- **interrupted/意外中断**：应用或进程异常退出，未走正常结束流程。
- **progress**：任务主动上报的百分比；没有上报时显示空，不代表卡死。

## 与其他页面协作

- 参数错误回到[运行工作台](05_运行工作台.md)修正任务配置。
- 代码/manifest 错误到[开发工作室](03_开发工作室.md)修复并重新保存包。
- Python、Kernel 或资源问题到[运行环境](12_运行环境.md)排查。
- 定时触发信息到[自动化计划](07_自动化计划.md)检查计划、并发与重试。

## 限制与安全

- 历史属于当前工作区；切换工作区会看到另一套记录。
- 运行“成功”只表示技术执行成功，不自动验证业务正确性。
- 日志、参数和产物路径可能包含客户名、文件名或业务数据，外发前脱敏。
- 删除计划不会删除历史记录；当前页面也不用于修改历史。
- 未登记为产物的临时文件可能存在于输出目录，但不会出现在产物列表。

## 常见问题与排错

- **找不到刚才的运行**：清空搜索，确认当前工作区，并等待提交完成。
- **进度不动但有新日志**：进度依赖脚本上报，以日志和最终状态为准。
- **成功却没有产物**：脚本可能未按 manifest 登记，打开输出目录并检查入口代码。
- **只有“意外中断”**：检查应用是否被关闭、系统是否重启或运行环境进程是否被终止。
- **复制日志后内容太多**：先按级别和关键词筛选；复制只取当前筛选结果。
- **参数中看不到密码**：敏感值不应持久化明文，这是预期行为。
