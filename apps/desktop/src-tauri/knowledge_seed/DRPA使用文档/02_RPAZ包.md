# RPAZ 包

## 页面用途

“RPAZ 包”管理当前工作区内已安装、可由宿主校验和运行的 `.rpaz` 自动化包。它是开发成果进入运行工作台和自动化计划的交接点。

## 适用场景

- 安装同事或外部系统交付的 `.rpaz`。
- 搜索、检查版本和运行环境。
- 从已安装包进入参数配置与运行。
- 接收开发工作室“保存到 RPAZ 包”的本地成果。

## 前置条件

- 外部安装需要一个可读的 `.rpaz` 文件。
- 包应包含合法 `manifest.yaml` 和声明的入口文件。
- 自建包建议先在[开发工作室](03_开发工作室.md)完成校验与测试。

## 界面区域

1. **页面操作区**：“安装 RPAZ 包”打开文件选择器。
2. **搜索框**：按名称、包 ID 或运行环境过滤。
3. **视图切换**：网格/列表仅改变展示方式。
4. **包卡片/列表项**：显示名称、说明、版本、运行时和信任状态。
5. **空状态**：可跳转开发工作室新建项目。

## 安装与使用流程

### 安装外部包

1. 点击“安装 RPAZ 包”并选择 `.rpaz`。
2. 等待路径、压缩规模、manifest、入口和声明文件校验。
3. 成功后在列表中搜索包名或 ID。
4. 选择包及其任务配置，进入[运行工作台](05_运行工作台.md)。

也可以把一个或多个 `.rpaz` 拖入桌面窗口；若当前页面专门接收其他文件类型，应先回到普通导航页再拖入。

### 接收本地开发项目

1. 在开发工作室完成项目与 manifest。
2. 点击“保存到 RPAZ 包”。
3. 回到本页确认版本、参数与运行时。
4. 前往运行工作台预检，避免把“保存成功”误当成“运行成功”。

## 字段与状态解释

- **ID**：包的稳定标识；同名包应依赖 ID 和版本区分。
- **Version**：来自 manifest；每次兼容性变化应更新。
- **Runtime**：声明的执行环境。
- **verified/local/untrusted**：表示来源和校验级别，不代表业务代码绝对安全。
- **参数/Profiles**：参数由 manifest 声明，任务配置在运行工作台创建。

参数 `id` 仍使用稳定的英文标识供代码读取；若界面需要中文标题，请增加 `label`，并可用 `description` 写字段说明：

```yaml
parameters:
  - id: customer_name
    label: 客户名称
    description: 用于报表标题
    type: string
    required: true
```

运行代码继续从 `ctx.params["customer_name"]` 取值，中文只负责显示，因此改文案不会破坏脚本接口。

- [运行工作台](05_运行工作台.md)：填写参数和实际运行。

- [运行记录](06_运行记录.md)：审计每次执行。

## 限制与安全

- 安装校验防止越界路径和异常压缩，但不能证明脚本业务逻辑可信。
- 不要安装来源不明、需要过宽文件或网络权限的包。
- API Key、密码和令牌不得打包进源码或 manifest。
- 普通 Agent 项目不会自动成为 RPAZ；必须具备规范和入口。
- 覆盖或升级前确认旧任务配置是否仍与新参数结构兼容。

## 常见问题与排错

- **安装按钮无反应**：桌面宿主之外的浏览器预览不能打开系统文件选择器；请运行桌面版。
- **提示 manifest 无效**：到开发工作室检查 YAML 缩进、ID、版本、入口和参数类型。
- **列表里找不到刚保存的包**：清空搜索条件并确认仍在同一工作区。
- **包能安装但不能运行**：安装只验证结构；到运行工作台预检，再在运行记录查看入口错误。
- **升级后任务参数错误**：新 manifest 改变了参数，重新创建或修正任务配置。
