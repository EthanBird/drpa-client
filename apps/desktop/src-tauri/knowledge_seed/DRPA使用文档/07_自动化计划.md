# 自动化计划

## 页面用途

“自动化计划”把已验证的 RPAZ 任务交给本机调度器，支持每日、每周、固定间隔和 Cron，提供并发策略、超时、重试及多目标投递。

## 适用场景

- 每天生成新闻摘要或数据报告。
- 每周运行固定 RPAZ 任务。
- 按间隔抓取数据或检查系统。
- 把一次结果同时广播到应用内通知、邮件、Webhook 或频道。
- 需要保留每次尝试和投递结果的本地自动化。

## 前置条件

- 当前工作区已有经过[运行工作台](05_运行工作台.md)验证的 RPAZ 包和配置。
- 本机在计划时间处于开机且 DRPA 调度服务可运行状态。
- 投递目标所需网络、地址和凭据已准备。
- 参数 JSON 格式正确。

## 界面区域

1. **顶部指标与模板**：计划数量、启用数、运行中/排队、投递目标和快捷模板。
2. **左侧计划列表**：搜索、选择计划，查看启用状态和下次运行。
3. **计划详情**：规则、目标、并发、投递和最近运行。
4. **编辑器**：基础信息、运行时间、执行策略和多目标投递。
5. **计划管理**：启用/暂停、立即运行、编辑和删除。

## 创建计划流程

1. 点击“新建计划”或选择模板。
2. 填写名称、说明，选择 RPAZ 包和运行配置。
3. 填写参数 JSON；先使用已验证配置作为基线。
4. 选择时间：
   - 每天：指定本机时间；
   - 每周：指定星期与时间；
   - 固定间隔：至少 1 分钟；
   - Cron：五段表达式，如 `0 8 * * 1-5`。
5. 选择并发策略：
   - **跳过**：已有实例时不再启动；
   - **并行**：允许多个实例同时执行。
6. 设置超时、最大尝试次数、重试间隔和退避倍数。
7. 按需添加投递目标；不添加时结果只保留本地历史。
8. 保存后先点击“立即运行”，在运行历史和[运行记录](06_运行记录.md)验收。
9. 验证完成再启用正式调度。

## 字段与状态解释

- **enabled/已启用**：会计算下次运行并由调度器触发。
- **paused/已暂停**：配置保留但不自动触发。
- **nextRunAt**：按本机时区计算的下一次时间。
- **timeoutSeconds**：单次尝试上限，不包括之后的重试等待。
- **maxAttempts**：总尝试次数，包含第一次。
- **delay/backoff**：每次失败后等待时间及增长倍数。
- **delivery target enabled**：只控制该目标，不影响任务本身运行。

## 与其他页面协作

- 包与任务配置来自[RPAZ 包](02_RPAZ包.md)和[运行工作台](05_运行工作台.md)。
- 每次执行详情进入[运行记录](06_运行记录.md)。
- 投递或脚本故障回到[开发工作室](03_开发工作室.md)修改。
- 复杂多节点、AI 分支和知识检索可改用[流程设计](08_流程设计.md)。

## 限制与安全

- 调度使用本机时区并精确到分钟；修改系统时间/时区后必须复核。
- 本机关机或调度服务不运行时，不能保证补跑错过的触发。
- 正在运行的计划不能删除；暂停不终止已经开始的实例。
- 并行策略可能重复访问同一文件、账号或外部系统，脚本必须具备幂等性。
- 投递 JSON 不应包含明文密钥；优先使用凭据引用或受控插件配置。
- 删除计划不会删除既有运行历史。

## 常见问题与排错

- **下次运行时间不对**：检查本机时区、夏令时和计划类型。
- **Cron 保存失败**：必须是五段，不使用秒字段；先从简单表达式验证。
- **计划被跳过**：并发策略为“跳过”且已有实例运行；查看详情中的运行状态。
- **重复执行**：检查是否选择“并行”、是否存在两个相似计划，以及脚本是否自行重试。
- **投递失败但任务成功**：运行和投递是不同阶段；检查目标配置与网络。
- **立即运行成功、定时不触发**：确认计划已启用、应用/调度服务在运行且下次时间正确。
