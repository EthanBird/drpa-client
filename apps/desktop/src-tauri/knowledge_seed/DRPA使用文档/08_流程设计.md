# 流程设计

## 页面用途

“流程设计”是本地 Dify 兼容开发平台，支持 Chat、Completion、Workflow 和 Chatflow。可配置 OpenAI 兼容 Provider、可视化编排节点、调试运行、检查历史、发布本地 API，并导入/导出 Dify DSL。

## 适用场景

- 构建带 Prompt 的聊天或单次生成应用。
- 把 LLM、条件、代码、知识检索、RPAZ 和输出组合成流程。
- 在本机调试 Dify DSL 后再迁移到兼容平台。
- 向本机程序提供 Dify 风格 API。

## 前置条件

- 至少一个可调用的 OpenAI Chat Completions 兼容 Provider。
- Workflow/Chatflow 需要明确输入、输出和节点变量。
- RPAZ 节点需要当前工作区已安装对应包。
- 知识检索节点需要[知识库](10_知识库.md)已有就绪索引。

## 界面区域

1. **顶部操作**：导入 DSL、管理 Providers、新建流程。
2. **左侧流程目录**：切换流程并查看 Provider 状态；底部显示本地 Service。
3. **流程标题栏**：删除、导出 DSL、发布。
4. **工作区页签**：
   - 工作流：节点画布与检查器；
   - 调试预览：输入消息并运行；
   - 流程配置：基本信息、输入、Prompt 与开场白；
   - 运行记录：输入输出、Provider、Token 和耗时；
   - API 与导出：Service、Token 和兼容性检查。

## 从零创建最小可运行流程

1. 打开 “Providers” → 新建 Provider。
2. 填写名称、模型、兼容 URL、上下文、最大输出、超时和流式开关；需要时输入 API Key。
3. 保存后点击“测试”，确认连接成功。
4. 点击“新建流程”，选择模式：
   - Chat：多轮对话和开场白；
   - Completion：单次文本生成；
   - Workflow：自动化/批处理；
   - Chatflow：带流程编排的对话。
5. Chat/Completion 在“流程配置”写系统指令、输入变量和 Provider。
6. Workflow/Chatflow 先搭最短链：Start → LLM → Answer/End。
7. 保存后进入“调试预览”，输入一句确定性测试并运行。
8. 查看运行记录，确认 Provider、输出和 Token。
9. 再逐个加入条件、代码、RPAZ、知识检索等节点，每次只增加一个变量来源并重新调试。

## 节点与变量理解

- **Start**定义流程输入。
- **LLM**消费上游变量并调用 Provider。
- **Answer/End**明确最终输出；没有终点的图不能形成完整结果。
- **Condition**按值分支，每条可能路径都应连接到有效终点。
- **Code**执行受控逻辑，输入/输出名要与后续节点一致。
- **Knowledge Retrieval**查询当前工作区知识库并返回带引用片段。
- **RPAZ**调用已安装包；需要映射参数并处理运行结果。
- 节点配置中的变量通常引用上游输出，不是任意全局变量。

## 发布与 API

1. 保存当前流程。
2. 在“API 与导出”运行兼容性检查，修复 error；warning 也应评估。
3. 点击“发布”，生成本地版本和应用 API Token。
4. 选择 1024–65535 端口并启动 Local Dify Service。
5. 本机客户端使用显示的 `http://127.0.0.1:<port>/v1` 与 Bearer Token 调用。
6. 需要云端迁移时导出 `.yml/.yaml` DSL，再在目标平台复核 Provider 映射和本机专属节点。

## 字段与状态解释

- **providerId/model**：实际调用连接与模型。
- **contextWindow/maxOutputTokens**：模型上下文与单次输出限制。
- **Streaming/Blocking**：增量或一次性响应。
- **publishedVersion**：最近本地发布版本；草稿修改不自动更新已发布版本。
- **apiEnabled**：发布后可通过 Token 调用。
- **compatible**：可导出到目标 DSL 版本，不等于目标环境一定有相同模型或插件。

## 与其他页面协作

- RPAZ 节点来自[RPAZ 包](02_RPAZ包.md)，执行详情可进入[运行记录](06_运行记录.md)。
- 知识检索来自[知识库](10_知识库.md)。
- Provider 或工具可由[插件](11_插件.md)贡献。
- 单 Agent 的自由对话、项目开发和文档处理使用[AI Agent](09_AI_Agent.md)。

## 限制与安全

- Service 应保持监听 `127.0.0.1`；不要在未知网络边界对外暴露。
- API Token、Provider Key 不得进入 DSL、日志、截图或知识文档。
- 删除流程会删除配置和本地 Token，历史运行仍保留。
- Dify 兼容导出无法保证本机 RPAZ、插件或文件路径在云端存在。
- 条件和迭代可能造成未覆盖分支或高调用量；先用小输入验证。

## 常见问题与排错

- **工作流太复杂、跑不通**：退回 Start → 单节点 → End，逐个增加节点；检查每个变量引用和所有分支。
- **调试按钮禁用**：输入为空、正在运行或 Provider 未配置。
- **Provider 测试失败**：确认 URL 通常以 `/v1` 结尾、模型名存在、服务已启动、Key 正确。
- **发布检查失败**：打开兼容性详情，优先处理 error，再处理本机依赖 warning。
- **API 返回未授权**：流程需先发布，并使用当前应用 Token，不要混用其他流程 Token。
- **导入 DSL 后节点缺失**：目标 DSL 含尚不支持或无法映射的节点；先看兼容性报告并手工替换。
